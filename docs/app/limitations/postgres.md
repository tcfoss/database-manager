# PostgreSQL Limitations

The following sections cover the restrictions on valid PostgreSQL SQL in
database definitions.


## Explicit Names

Tables, columns, types, domains, routines, and triggers must have explicit
declaration names. PostgreSQL's stored-identifier rules apply: unquoted names
fold ASCII uppercase letters to lowercase, quoted names preserve case, and
names are truncated to 63 UTF-8 bytes at character boundaries.


### PRIMARY KEY, UNIQUE, FOREIGN KEY, and CHECK constraints must be named

Every such table constraint must include `CONSTRAINT <name>`. PostgreSQL can
generate these names, but its choices can depend on existing names and
declaration order, making them unsuitable for stable definition comparison.

This requirement also applies to supported column-level `PRIMARY KEY`,
`UNIQUE`, and `CHECK` clauses. Put `CONSTRAINT <name>` before the clause, or
declare the constraint at table level.

```sql
-- Not supported
CREATE TABLE accounts (id BIGINT PRIMARY KEY);

-- Supported
CREATE TABLE accounts (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    email TEXT NOT NULL,
    parent_id BIGINT,
    CONSTRAINT accounts_pk PRIMARY KEY (id),
    CONSTRAINT accounts_email_uq UNIQUE (email),
    CONSTRAINT accounts_parent_fk FOREIGN KEY (parent_id) REFERENCES accounts (id),
    CONSTRAINT accounts_id_positive_ck CHECK (id > 0)
);

-- A named column-level constraint is also supported
CREATE TABLE categories (
    id INT CONSTRAINT categories_pk PRIMARY KEY
);
```

### Domain CHECK constraints must be named

Use an explicit `CONSTRAINT <name>` for each domain `CHECK`:

```sql
CREATE DOMAIN positive_int AS INTEGER
    CONSTRAINT positive_int_positive CHECK (VALUE > 0);
```

### Standalone indexes must be named

Both `CREATE INDEX` and `CREATE UNIQUE INDEX` require an explicit index name:

```sql
CREATE INDEX accounts_parent_idx ON accounts (parent_id);
```

### Names that may remain implicit

`NOT NULL` constraint names and identity backing-sequence names may be omitted;
these components are identified through their owning column. Routine parameter
names may also be omitted, since parameters have a stable argument position.
